# WP5-B 下一步：跨任务扩展与闭环准入设计

日期：2026-10-15。此轮只使用已归档候选与响应，**没有发送 API 请求**。版本化任务清单位于 `runs/wp5b_task_diversification_v1/`；它是待审实验 roster，**不是已授权的付费请求计划**。

## 样本框的实际约束

历史 Agent 消息可遮蔽的候选决策有 506 个，但只覆盖 **57 个不同任务**；其中 TEST 标记仅 **8 个不同任务**。已完成的 WP5-B 干预占了 6 个 TEST 任务，因而原样本框最多还能增加 2 个未干预的 TEST 任务。增加同任务重复可以改善该任务的局部分布估计，却不能补足跨任务有效样本量。

一个直观上界：假设任务独立同分布、且 8 个 TEST 任务均未观察到某个预注册差异，单侧 95% 二项上界仍约 **31.2%**；要把“零差异”上界压到 10% 以下，至少需要 **29 个独立任务**，压到 5% 以下需 **59 个**。这里的独立同分布假设对当前人工筛选 roster 并不成立；这些数是样本量警示，**不是当前研究的置信区间**。现有 TEST 样本框根本不能支持强的总体无差异结论。

## 本轮具体推进

从之前未选中的任务中固定了 **12 个不同任务、12 个决策**，并逐条查看了被遮蔽的 Agent 文本与最新用户文本；与前次 12 个任务无重叠。构成为：TEST 2 个（retail、telecom 各 1）、VALIDATION 8 个（airline/retail/telecom 为 3/3/2）、TRAIN 2 个（airline、retail 各 1）。按遮蔽后用户请求的语境依赖预先分为高 6、低 6。低依赖仅表示最新用户消息连同**其他未遮蔽历史**仍较易理解，绝不预断处理结果或认定该 Agent 文本无因果作用。每条记录保存原请求引用与哈希、决策/任务 ID、split、分层和人工理由代码，不复制私人样式的 benchmark 文本进报告。

这 12 个任务是针对机制对照的目的性补充，不是概率样本：新的 TEST 2 个可作为尚未做过本干预的 TEST-tagged 扩展；VALIDATION 8 个只用于探索/方法检查；TRAIN 2 个只用于诊断。不能把 12 个混合起来声称有 12 个新的 held-out 测试任务。连同此前 12 个任务，当前有 24 个不同任务进入本研究的已选/待选清单，但只有此前 12 个已有干预响应。

## 拟预注册的判定方式（未执行）

1. Agent-only 的任务级主终点：规范化的下一步工具名、参数及调用顺序；另记粗动作、最终可见答复类别与 provider 未报告的 token 细项。A 原文、B 遮蔽、C 问候语 placebo 交错随机派发。同一任务的重复必须聚合后再跨任务统计；比较 B–C 的改变是否超过 A–C 的背景波动，并分开报告高/低语境依赖。单次响应 ID、总 tokens 或精确措辞不作为独立任务或主要效果。
2. 完整任务终点须另做 Closed-loop：不仅看下一步读工具，还要记录合法写操作、环境副作用、终局与适用的 benchmark grader 结果；不得用 Agent-only 搜索结果冒充任务完成。只有同一锚点两次独立恢复在 Agent 有效请求、消息历史、用户模拟器私有状态、环境/工具状态、待执行动作及轮次等预注册 signature 上合格，才可标为 `READY_CLOSED_LOOP`。
3. 当前严格合格的 Closed-loop 检查点仍为 **0**。已有离线恢复试点证明部分 Agent/环境快照能重建，但 provider 侧用户模拟器隐状态与完整分叉隔离尚未被验证。因此 Closed-loop 目前不进入付费执行；如果状态无法恢复，保留 Agent-only 结果并明确标 `BLOCKED_BY_STATE_RECOVERY`。

若用户后续决定执行这份扩展，需要先对 12 个源请求做完整语义审阅、冻结具体三臂请求和重复/交错方案、估算 tokens/费用并单独确认新硬上限。此前 WP5-B 授权已用于完成上一轮，不自动结转。本轮新增 API attempts、付费 tokens、Closed-loop branches 均为 **0**。
